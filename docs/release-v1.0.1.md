## ssh_tunel 1.0.1

Локальная сеть больше не пропадает при включённом туннеле.

### Что изменилось

**Локальные адреса идут мимо туннеля.** Раньше обращение к `192.168.1.50` уходило
на сервер, и сервер искал этот адрес в своей сети — домашние сервисы (роутер,
NAS, Home Assistant, локальные серверы разработки) при включённой программе
переставали открываться. Теперь такие цели всегда выходят напрямую, в любом
режиме фильтра.

Локальным считается:

- адрес из `10/8`, `172.16/12`, `192.168/16`, `127/8`, `169.254/16`, `100.64/10`,
  `::1`, `fc00::/7`, `fe80::/10`;
- имя без единой точки — `homeassistant`, `nas`;
- имя с окончанием `.local`, `.lan`, `.home`, `.internal`, `.localdomain`,
  `.home.arpa`, `.ts.net`, `.netbird.cloud`.

**Mesh-VPN учтены отдельно.** `100.64.0.0/10` — диапазон, из которого раздают
адреса NetBird, Tailscale и подобные. Устройство с адресом `100.104.x.x`
достижимо только через свой VPN-клиент, поэтому такие соединения тоже идут
напрямую. Исключается именно `100.64/10`, а не вся сотая сеть: её первая
половина — обычные публичные адреса.

**Свой список «всегда напрямую».** Новое поле в настройках — для сетей, о
которых программа знать не может: корпоративный VPN, самодельный WireGuard,
Hamachi с его `25.x.x.x`. Формат любой, каким удобно написать:

```
10.8.0.0/16      сеть в записи CIDR
25.*  10.8.*     то же шаблоном
100.104.1.5      одиночный адрес
.corp.local      любое имя с таким окончанием
```

В консольной версии — флаг `-direct` со списком через запятую.

**Обратный случай тоже возможен.** Если нужна внутренняя сеть самого сервера —
галочка «Локальную сеть тоже вести через сервер» в настройках, флаг
`-local-via-tunnel` в консоли.

**Консольная версия для Windows больше не публикуется.** Окно умеет всё то же
самое, а лишний файл на странице скачивания только сбивал с толку. Исходники на
месте, собирается одной командой:
`GOOS=windows go build -o ssh_tunel-cli.exe ./cmd/ssh_tunel-cli`.

Тексты в программе и в документации переписаны: акцент на том, что это учебный
проект про устройство SSH, SOCKS и HTTP CONNECT.

### Что скачивать

| Система | Файл |
|---|---|
| Windows 10 / 11 | `ssh_tunel.exe` — окно с кнопкой и значком у часов |
| Linux (обычные серверы) | `ssh_tunel-linux` |
| Linux ARM (Raspberry Pi и подобное) | `ssh_tunel-linux-arm64` |

Обновление: просто заменить файл. Настройки лежат отдельно и переносятся сами,
новая настройка про локальную сеть встанет в безопасное положение без правки
конфига.

### Что умеет

- **Три протокола сразу** — SOCKS5, SOCKS4/4a и HTTP CONNECT: разные
  программы умеют разное, и нужны все три.
- **Разделение трафика по программам** — через туннель идёт всё, только
  выбранные приложения, или всё кроме выбранных. Правила меняются на ходу,
  без переподключения.
- **Локальная сеть остаётся доступной** — роутер, NAS, Home Assistant и узлы
  mesh-VPN идут напрямую, а не через сервер.
- **Работает там, где системный прокси бессилен** — Node.js, Python, Go и всё
  на них (npm, pip, curl) читают только переменные окружения, и программа их
  прописывает.
- **Переживает обрывы связи** — пул SSH-соединений с проверкой живости и
  переподключением. Заснувший ноутбук не ломает туннель.
- **Возвращает настройки как было** при любом закрытии, включая аварийное:
  интернет после выхода не пропадает.
- **Проверяет ключ сервера** — подмена сервера по дороге не пройдёт незаметно.
- **Меряет реальную скорость** — тест в несколько потоков через туннель.
- **Видно, кто ходит в интернет** — живой список программ и адресов, с
  пометкой, если DNS-запрос ушёл мимо туннеля.

### Windows

Запустить двойным щелчком. Windows предупредит о неизвестном издателе —
«Подробнее» → «Выполнить в любом случае»: программа не подписана сертификатом.
Дальше настройки (шестерёнка), адрес сервера, круглая кнопка. Крестик прячет
программу в трей, туннель продолжает работать.

### Linux

```bash
chmod +x ssh_tunel-linux
./ssh_tunel-linux -host ТВОЙ_СЕРВЕР -user root -save
./ssh_tunel-linux -web      # тот же интерфейс на 127.0.0.1:47821
```

Служба systemd и установщик — в `packaging/linux`.

### Чего туннель не покрывает

- Программы со своим сетевым стеком, игнорирующие и системный прокси, и
  переменные окружения — часть игр, некоторые мессенджеры.
- UDP целиком: SSH пробрасывает только TCP.
- DNS-запросы приложений, которые резолвят имена сами, до обращения к прокси.
  Такие соединения помечаются в журнале.
- Локальную сеть — намеренно, чтобы домашние сервисы оставались доступны.
