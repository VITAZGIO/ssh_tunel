# Что делать, когда не работает

## Claude Code, установленный локально, отдаёт 403

Самая частая и самая непонятная проблема: Claude Desktop работает, облачный
Claude Code работает, а локально установленный — выдаёт 403.

**Почему так.** Ответ 403 означает, что запрос **дошёл** до серверов Anthropic и
там его отклонили по географии. То есть трафик шёл не через туннель, а напрямую,
с российского адреса. Причина — в том, кто какие настройки прокси читает:

| Программа | На чём написана | Читает системный прокси Windows? |
|---|---|---|
| Claude Desktop | Electron (движок Chromium) | **Да** — поэтому работал |
| Claude Code в облаке | выполняется не у тебя | вопрос не стоит |
| Claude Code локально | Node.js | **Нет** — поэтому 403 |

Node.js системные настройки прокси из реестра Windows не читает вообще, никогда.
Он смотрит только на переменные среды `HTTP_PROXY` / `HTTPS_PROXY`, и понимает
там только адреса вида `http://...` — схему `socks://` встроенный HTTP-клиент
Node не поддерживает. А старая версия программы поднимала **только** SOCKS-прокси
и прописывала **только** системный прокси. Для Node.js это было равно отсутствию
туннеля.

**Что исправлено.** Теперь программа поднимает ещё и HTTP-прокси (по умолчанию
порт 1081) и, если галочка включена, сама прописывает переменные среды
пользователя:

```
HTTP_PROXY  = http://127.0.0.1:1081
HTTPS_PROXY = http://127.0.0.1:1081
NO_PROXY    = localhost,127.0.0.1
```

**Что нужно сделать тебе.** Переменные среды подхватываются только процессами,
запущенными **после** их установки. Уже открытый терминал их не увидит. Поэтому:

1. Включи туннель.
2. Закрой терминал (PowerShell / cmd / Windows Terminal) полностью.
3. Открой заново и запусти `claude`.

Проверить, что переменная на месте:

```powershell
echo $env:HTTPS_PROXY
```

Должно напечатать `http://127.0.0.1:1081`. Если пусто — терминал открыт до
включения туннеля, перезапусти его.

**Если не хочешь менять переменные среды глобально** — сними галочку и вставляй
в терминал вручную перед запуском:

```powershell
$env:HTTPS_PROXY="http://127.0.0.1:1081"
$env:HTTP_PROXY="http://127.0.0.1:1081"
$env:NO_PROXY="localhost,127.0.0.1"
claude
```

**Проверить, что помогло:**

```powershell
curl.exe -x http://127.0.0.1:1081 https://api.ipify.org
```

Должен вернуться адрес сервера, а не твой домашний.

Тот же приём чинит `npm`, `pip`, `git`, `curl`, `docker pull` и вообще всё, что
написано не на технологиях Microsoft.

## Пропал интернет после того, как программа закрылась

Раньше такое случалось: если программа падала или окно консоли закрывали
крестиком, системный прокси оставался включённым, и Windows продолжала слать
весь трафик на порт, который уже никто не слушает.

Сейчас это лечится тремя способами сразу:

- перехватывается не только Ctrl+C, но и закрытие окна, выход из системы и
  завершение работы;
- прежние настройки сохраняются на диск и восстанавливаются ровно такими, какими
  были (раньше они просто затирались);
- при следующем запуске программа замечает, что настройки остались от аварийно
  завершённого прошлого раза, и чинит их сама.

Если всё же понадобилось починить вручную:
Параметры → Сеть и Интернет → Прокси-сервер → выключить «Использовать
прокси-сервер».

## Программа говорит, что ключ сервера изменился

```
ключ сервера 87.58.210.143 отличается от запомненного
```

Два варианта:

- **Ты переустанавливал сервер или менял его ключи.** Тогда всё в порядке: удали
  строку с этим адресом из `%APPDATA%\ssh_tunel\known_hosts` и подключись
  заново — новый ключ запомнится.
- **Ты ничего не менял.** Тогда подключаться нельзя: это выглядит как попытка
  подмены сервера. См. [SECURITY.md](SECURITY.md).

## Скорость ниже, чем без туннеля

Часть падения неизбежна: трафик идёт лишние несколько тысяч километров и
шифруется дважды. Что можно подкрутить:

- **Каналов SSH** в настройках. Одно TCP-соединение упирается в одно окно
  перегрузки — на канале с задержкой это и есть главный потолок. Значения 4–8
  обычно дают заметный прирост; больше 8 редко помогает.
- **Проверь загрузку процессора на сервере.** Если это дешёвый тариф с одним слабым
  ядром, потолок задаёт он, а не сеть.
- **Проверь, что сервер выбрал AES-GCM.** Программа просит его первым, потому что
  он аппаратно ускорен на любом современном процессоре. Если на сервере старый
  OpenSSH с ограниченным набором шифров, скорость упрётся в программный
  chacha20.

## Что-то не идёт через туннель

Проверь в окне, в разделе «Кто ходит в интернет» — если приложения там нет
вовсе, значит оно ходит мимо прокси. Такое бывает у игр и программ со своим
сетевым стеком. Для них помогает либо собственная настройка прокси внутри самой
программы, либо ничего.

Если у приложения есть настройки прокси — укажи `127.0.0.1:1081` (HTTP) или
`127.0.0.1:1080` (SOCKS5).

## Порт занят

```
не могу занять локальный адрес 127.0.0.1:1080 — возможно, программа уже запущена
```

Либо программа уже работает в другом окне, либо порт занят чем-то другим.
Поменяй порты в настройках или закрой вторую копию.

## Окно не открывается / «не найден компонент WebView2»

Окно рисуется движком Edge (WebView2). В Windows 10 и 11 он стоит по умолчанию
вместе с Edge, но в сильно урезанных сборках его может не быть.

Варианты:

- поставить «Microsoft Edge WebView2 Runtime» с сайта Microsoft (маленький
  установщик, прав администратора не требует);
- либо пользоваться туннелем без окна — запусти `ssh_tunel.exe -nowindow`,
  программа напечатает адрес, который открывается в любом браузере.

## Закрыл окно, а программа осталась висеть

Так и задумано: крестик прячет окно в трей, чтобы случайное закрытие не рвало
туннель посреди работы. Значок программы — у часов, рядом с «безопасным
извлечением устройства»; если его не видно, нажми стрелку «Показать скрытые
значки».

Правый щелчок по значку → «Выход» завершает программу полностью и возвращает
настройки прокси на место.

## Запустил второй раз, ничего не произошло

Вторая копия не запускается специально — она всё равно не смогла бы занять уже
занятые порты. Вместо этого показывается окно уже работающей программы.

## Что показывает тест скорости

Кнопка на главном экране измеряет пропускную способность **через туннель**:
качает и отдаёт данные на публичные точки Cloudflare, те же, что использует их
собственный измеритель. Занимает около двадцати секунд, результат появляется в
плитках «Приём» и «Отдача».

Две детали, из-за которых цифра честная:

- **Потоков столько же, сколько каналов SSH.** Одно соединение упирается в
  одно окно перегрузки, и один поток на дальнем канале показал бы в разы
  меньше реального потолка. Меряется ровно то, чем пользуется браузер.
- **Первая секунда не считается.** Соединение в начале только раскачивается, и
  если учитывать разгон, результат занижается.

Если хочется выжать больше — увеличь «Каналов SSH» в настройках и прогони тест
снова. Значения 4–8 обычно дают заметный прирост, больше 8 редко помогает.

Тест нагружает канал полностью, поэтому во время него интернет будет
подтормаживать — это нормально.

## Иконка осталась старой

Проводник кэширует значки файлов и после замены exe часто продолжает
показывать прежнюю картинку. Сама программа тут ни при чём: в заголовке окна
и в трее иконка берётся из ресурсов на лету и меняется сразу.

Сбросить кэш:

```powershell
taskkill /f /im explorer.exe
del /a /q "%LocalAppData%\IconCache.db"
del /a /q "%LocalAppData%\Microsoft\Windows\Explorer\iconcache*"
start explorer.exe
```

Быстрее и проще — переименовать exe или положить его в другую папку: кэш
привязан к пути.

Если иконка не появляется и в заголовке окна, значит в exe действительно
что-то не то — напиши, посмотрю.

## Не открывается роутер / NAS / Home Assistant

Не должно такого быть: локальная сеть идёт мимо туннеля всегда, в любом режиме
фильтра. Локальным считается адрес из `10.x.x.x`, `172.16–31.x.x`,
`192.168.x.x`, `169.254.x.x`, `127.x.x.x`, а из имён — всё без точек
(`homeassistant`, `nas`) и всё с суффиксом `.local`, `.lan`, `.home`,
`.internal`, `.localdomain`, `.home.arpa`.

Если всё-таки не открывается, проверь по порядку:

1. **Не включена ли галочка «Локальную сеть тоже вести через сервер».** Она
   существует ровно для обратной задачи — дотянуться до внутренней сети самого
   сервера. Выключи и переподключись.
2. **Через какое имя ты ходишь.** Внешнее имя, которое ведёт на домашний адрес
   (`ha.example.com` → `192.168.1.50`), локальным не считается: программа видит
   только имя и отправит его на сервер. Ходи по адресу или по локальному имени.
3. **Настройка вступает в силу после переподключения**, если менялась при
   работающем туннеле: списки исключений системного прокси прописываются один
   раз при включении.

## Как пустить часть программ мимо туннеля

В настройках есть «Какие программы вести через туннель» с тремя режимами:

- **Все** — обычное поведение;
- **Только выбранные** — через туннель идут отмеченные программы, остальные
  выходят напрямую;
- **Все, кроме выбранных** — наоборот.

Экран открывается из настроек, строкой «Какие программы вести через туннель».
Кнопка «Добавить программу» предлагает три способа: выбрать из списка
запущенных (как в диспетчере задач, с поиском и путями), указать файл на
диске через обычный системный диалог, или вписать имя вручную.

Регистр, путь и отсутствие `.exe` значения не имеют: `Steam`, `steam.exe` и
`C:\...\steam.exe` — одно и то же.

Правила применяются сразу, переподключаться не нужно. В журнале соединения,
пущенные мимо, помечены как «мимо туннеля (по правилам)».

Два места, где это ведёт себя не так, как можно ожидать:

- **Неопознанные программы идут через туннель.** Определить владельца сокета
  удаётся не всегда. Выбран более безопасный вариант: лучше лишнее приложение
  внутри туннеля, чем неожиданная утечка мимо него.
- **Пустой список в режиме «только выбранные» ничего не отрезает.** Иначе он
  оставил бы без интернета вообще все программы.

Чего фильтр не может: программы, которые вообще не обращаются к прокси (часть
игр, приложения со своим сетевым стеком), туннель не видит — они идут мимо в
любом случае, и добавить их в туннель через этот список нельзя.

В консольной версии то же самое флагами:

```powershell
.\ssh_tunel-cli.exe -filter except -apps steam.exe,discord.exe
```

## Быстрая настройка на новом компьютере

В настройках, рядом с полем «Приватный ключ», есть знак вопроса. Он открывает
готовую команду: она создаёт ключ (если его ещё нет) и сразу кладёт его на
сервер. Адрес сервера и пользователь подставляются из полей формы, так что вводить
их второй раз не нужно.

Порядок: нажать «Открыть PowerShell» (команда при этом уже в буфере обмена),
вставить её и нажать Enter, ввести пароль от сервера. Больше пароль не понадобится
— дальше вход по ключу.

Команда не выполняется сама и не подставляется в терминал за тебя намеренно:
любой способ «напечатать за пользователя» либо запускает её сразу, либо
ломается от раскладки и задержек. Вставить самому — заодно видно, что именно
выполняется.

Путь к ключу программа определяет сама, по домашней папке текущего
пользователя: на другом компьютере и под другим именем он будет свой. Из
стандартных имён берётся первое существующее — `id_ed25519`, `id_ecdsa` или
`id_rsa`.

## Куда делись «Системный прокси» и «Переменные среды»

Убраны из окна: без них туннель никому не нужен — он работает, но трафик
через него сам собой не идёт, и программа показывала бы «подключено» при
неработающем интернете. Теперь в оконной версии они включены всегда.

Если нужно управлять ими вручную (например, на компьютере уже настроен свой
прокси, который нельзя трогать) — это осталось в консольной версии:

```powershell
.\ssh_tunel-cli.exe -sysproxy=false -setenv=false
```
