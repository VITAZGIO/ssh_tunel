# Сеть устройств

Твои устройства — компьютер, ноутбук, телефон, домашний сервер — видят друг
друга по постоянным адресам и именам, как в NetBird или Tailscale. Только
посредник — не чужой облачный сервис, а твой собственный сервер, тот же, через
который идёт туннель.

```
  ноутбук.mesh  ──SSH──►  твой сервер (meshd)  ◄──SSH──  сервер.mesh (дома)
  198.19.0.1                                             198.19.0.2
```

Пример: дома стоит сервер с Docker, у контейнера порт 8080. С ноутбука в кафе
открываешь `http://domashniy-server.mesh:8080` — и попадаешь в этот контейнер.
Белый адрес дома, проброс портов на роутере и открытые наружу порты не нужны:
оба устройства и так ходят к серверу по SSH.

## Как включить

1. **На сервере** — служба `meshd`. Её ставит мастер настройки VPS (галочка
   «Заодно поставить сеть устройств») или панель на сервере: вкладка «Сеть
   устройств» → «Главный сервер». Руками — см. ниже.
2. **На первом устройстве**: Настройки → Настройки сервера → «Сеть
   устройств» → «Включить». Ключ сети создастся сам. Имя устройства — любое,
   из него получится имя `.mesh` (кириллица переводится в латиницу).
3. **На остальных**: либо «Экспорт» сервера с первого устройства (ключ сети
   едет вместе с ним, на телефон — QR-кодом), либо вставить тот же ключ руками.

## Что работает

- Имена `имя.mesh` и адреса `198.19.x.y` — в режиме прокси (браузер, curl,
  всё, что ходит через прокси) и в режиме VPN (Windows, Linux, Android — там
  любая программа).
- Адрес устройства постоянный: сервер запоминает его по id устройства.
- Входящие: «Пускать другие устройства к моим службам» — тогда
  `устройство.mesh:ПОРТ` ведёт на `127.0.0.1:ПОРТ` этого устройства. Выключи
  там, куда ходить не нужно (например, на телефоне).
- Сети разных людей на одном сервере разделены ключом: видят друг друга только
  устройства с одинаковым ключом. Сервер хранит не ключ, а его хеш.

## Несколько серверов в одной сети

Серверов может быть сколько угодно: например, выход в интернет через Германию
у тебя и через Нидерланды у друзей — а устройства всё равно в одной сети.

```
  ноутбук ──SSH──► Москва (главный, meshd) ◄──SSH, meshlink── Германия ◄──SSH── телефон
                                           ◄──SSH, meshlink── Нидерланды ◄──SSH── планшет
```

- **Главный** сервер — один на сеть, на нём работает `meshd`, в его панели
  видна вся сеть.
- **Побочный** сервер своего `meshd` не держит: его `127.0.0.1:47831` — это
  SSH-проброс (`ssh -L`, служба `meshd-uplink`) к `meshd` главного. Устройства,
  подключённые к побочному серверу, ничего не знают и ничего не настраивают
  отдельно: они ходят к `127.0.0.1:47831` своего сервера, как обычно.

Как подключить побочный сервер (нужна панель на обоих):

1. Панель главного → «Сеть устройств» → «Серверы сети» → «Подключить
   сервер» → имя → «Получить код».
2. Панель побочного → «Сеть устройств» → «Побочный сервер» → вставить код →
   «Подключить к главному». Через несколько секунд сервер появится на схеме.

Один код — для одного сервера. Внутри кода — адрес и SSH-ключи главного
(побочный проверяет, что говорит именно с ним) и отдельный ключ доступа для
побочного. На главном этот ключ принадлежит пользователю `meshlink`, которому
разрешено ровно одно — проброс до `127.0.0.1:47831`: ограничения стоят и в
`authorized_keys` (`restrict,port-forwarding,permitopen=…,command=nologin`), и
блоком `Match User meshlink` в `sshd_config` (без оболочки, без обратного
проброса и доступа к другим портам). «Отключить» в панели главного убирает
ключ и рвёт соединение.

## Панель на главном сервере

- Плитки: сколько устройств и серверов в сети, средняя задержка, трафик
  между устройствами.
- Схема сети: главный в центре, побочные вокруг, у каждого — его устройства;
  цвет и бегущие линии — живая связь и её качество.
- Карточка устройства: адрес и имя `.mesh`, система и версия программы,
  режим (прокси или VPN), через какой сервер подключено, задержка (RTT),
  джиттер, потери, трафик, сколько раз подключалось.
- Переименование прямо в карточке: новое имя `.mesh` сразу видят все
  устройства сети, в том числе само переименованное. «Убрать» освобождает
  адрес.

Задержку меряет сам `meshd`: раз в 15 секунд шлёт каждому устройству и
каждому побочному серверу ping с меткой времени. Через какой сервер пришло
устройство, панель узнаёт по адресу сервера из профиля устройства.

## Ограничения

- Только TCP (веб, SSH, базы, RDP по TCP…). UDP между устройствами пока нет.
- Весь трафик между устройствами идёт через сервер: скорость — не выше, чем
  у двух туннелей до него.
- Службе на устройстве надо слушать `127.0.0.1` или `0.0.0.0` (Docker с
  опубликованным портом — как раз так).

## Как устроено

`meshd` (`src/cmd/meshd`) слушает только `127.0.0.1:47831` на сервере — до
него дотягиваются лишь через SSH-туннель. Каждое устройство держит к нему
управляющее соединение: получает свой адрес, список устройств и вызовы. Когда
ноутбук открывает `сервер.mesh:8080`, он просит `meshd` соединить; `meshd`
зовёт домашний сервер по его управляющему соединению, тот открывает встречное
соединение, и `meshd` сшивает два потока. Клиентская сторона —
`src/internal/mesh`; в ядре туннеля такие цели идут в сеть устройств раньше
всех правил.

`meshd` — один файл на стандартной библиотеке Go: мастер скачивает готовую
сборку со страницы релиза, а если её нет — собирает прямо на сервере.

## Установка руками

```bash
# на сервере под root; для arm64 — meshd_arm64
curl -fsSL -o /usr/local/bin/meshd \
  https://github.com/VITAZGIO/ssh_tunel/releases/latest/download/meshd
chmod +x /usr/local/bin/meshd
cat > /etc/systemd/system/meshd.service <<'UNIT'
[Unit]
Description=ssh_tunnel - сеть устройств (только 127.0.0.1)
After=network.target

[Service]
ExecStart=/usr/local/bin/meshd -state /var/lib/meshd/state.json -admin /run/meshd/admin.sock
Restart=always
DynamicUser=yes
StateDirectory=meshd
RuntimeDirectory=meshd
NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes

[Install]
WantedBy=multi-user.target
UNIT
systemctl daemon-reload && systemctl enable --now meshd
```

Если пользователю туннеля закрыт доступ к самому серверу (шаг 3 в
[SERVER_SETUP.md](SERVER_SETUP.md)), в правилах нужно исключение для
`127.0.0.1:47830-47831` — в свежей версии скрипта оно уже есть.
