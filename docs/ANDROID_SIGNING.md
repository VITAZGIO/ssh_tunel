# Ключ подписи приложения

Делается **один раз**. Дальше про него можно забыть — сборка релиза подписывает
APK сама.

---

## Зачем

Android опознаёт приложение не по имени, а по ключу, которым оно подписано.

Обновление ставится поверх старой версии только тогда, когда ключ **тот же
самый**. Подписанное другим ключом система считает посторонним приложением: она
откажется его ставить и потребует сначала удалить прежнее — вместе со всеми
настройками, ключом от сервера и списком приложений.

До сих пор APK собирался в отладочном режиме, а его ключ создаётся заново на
каждой машине и в каждой сборке. То есть каждая новая версия требовала снести
предыдущую. Постоянный ключ это прекращает.

> Ключ нельзя потерять и нельзя восстановить. Потеряешь — обновлять уже
> установленное приложение будет нечем, останется только выпустить его заново
> под другим именем. Файл и пароль стоит положить туда же, где лежат остальные
> важные пароли.

---

## Шаг 1. Создать ключ

Нужен `keytool` — он идёт вместе с Java. Если её нет:

```powershell
winget install --id EclipseAdoptium.Temurin.21.JDK -e
```

После установки **закрой и открой PowerShell заново**, иначе он не увидит новую
команду.

Дальше — одной строкой. Придумай пароль и подставь его вместо `ПАРОЛЬ` в обоих
местах (пароль на хранилище и на сам ключ делаем одинаковым: разные ничего не
добавляют, а перепутать их легко):

```powershell
keytool -genkeypair -v -keystore "$env:USERPROFILE\ssh_tunnel-release.jks" -alias ssh_tunnel -keyalg RSA -keysize 4096 -validity 10000 -storepass ПАРОЛЬ -keypass ПАРОЛЬ -dname "CN=ssh_tunnel, O=VITAZGIO, C=RU"
```

`validity 10000` — это ~27 лет. Срок берётся с запасом намеренно: когда ключ
протухнет, обновлять приложение станет нечем.

---

## Шаг 2. Превратить файл в текст

В секретах GitHub хранится только текст, поэтому файл переводим в base64:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("$env:USERPROFILE\ssh_tunnel-release.jks")) | Set-Clipboard
```

Строка уже в буфере обмена — на экран она не выводится, и это правильно: в
истории терминала ей делать нечего.

---

## Шаг 3. Положить в секреты репозитория

**Settings → Secrets and variables → Actions → New repository secret.**

Четыре штуки:

| Имя | Значение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | вставить из буфера (шаг 2) |
| `ANDROID_KEYSTORE_PASSWORD` | твой пароль |
| `ANDROID_KEY_ALIAS` | `ssh_tunnel` |
| `ANDROID_KEY_PASSWORD` | тот же пароль |

Секреты видны только сборке. Обратно их не прочитать даже тебе — можно лишь
заменить.

---

## Шаг 4. Убрать старую версию с телефона

Один раз. Приложение, поставленное из прошлых сборок, подписано отладочным
ключом, и поверх него подписанное настоящим не встанет.

Удали его с телефона и поставь APK из релиза заново. Настройки и ключ от сервера
придётся ввести ещё раз — дальше обновления будут вставать поверх, ничего не
теряя.

---

## Как проверить, что всё сошлось

После выпуска релиза открой его сборку в **Actions** и найди шаг
«Переименовать и проверить подпись». Там напечатан отпечаток сертификата. У всех
следующих релизов он обязан быть **таким же** — если изменился, значит ключ
подменился, и обновление у людей не встанет.

---

## Если ключа нет

Сборка релиза остановится с понятным сообщением. Это сделано намеренно: молча
выпустить неподписанный APK хуже, чем не выпустить его вовсе — поломка вылезет
уже у человека при установке.

Отладочные сборки на каждый пуш (workflow `android`) ключа не требуют и работают
как раньше.
