# Панель управления сервером (ssh_tunnel_panel)

Отдельная программа, которая ставится **на сам VPS** и управляет подключёнными
к нему клиентами — в отличие от `ssh_tunnel_linux -web`, которая живёт на
компьютере клиента и доступна только с него самого.

Сейчас это каркас: вход по логину и паролю, состояние сервера, пустой список
клиентов. Подключение самих клиентов и работа с ними — отдельная задача.

## Панель работает от root — и это не забывчивость

Чтобы заводить, менять и удалять клиентов панели (в будущем — системные
учётные записи и права доступа), ей нужны права root. Это осознанное решение,
а не то, что «не успели поправить»: без root часть будущих задач панели просто
невыполнима.

Юнит systemd сужает всё остальное, что доступно этому процессу
(`ProtectHome=true`, `PrivateTmp=true`, `ProtectSystem=strict`, запись
разрешена только в `/etc/ssh_tunnel_panel`) — но сам факт запуска от root
никуда не девается, и если это неприемлемо для твоего сервера, панель тебе не
подходит.

## Установка

```bash
# на сервере, из папки со скачанным бинарём
sudo bash install.sh ./ssh_tunnel_panel
```

По умолчанию панель слушает только `127.0.0.1:47823` — рассчитано на то, что
домен и TLS даёт стоящий перед ней nginx/Caddy. Два других варианта:

```bash
sudo bash install.sh ./ssh_tunnel_panel --lan
# панель на всех интерфейсах, порт 47823 открывается в ufw — без TLS,
# годится для теста или доверенной сети

sudo bash install.sh ./ssh_tunnel_panel --domain=panel.example.com
# свой HTTPS со встроенным автосертификатом Let's Encrypt
# (golang.org/x/crypto/acme/autocert), порты 80 и 443
```

Установщик поднимает systemd-службу `ssh_tunnel_panel`, открывает нужный порт
в ufw (если он включён) и печатает адрес панели и логин с одноразовым паролем
из журнала службы — их же в любой момент можно посмотреть так:

```bash
sudo journalctl -u ssh_tunnel_panel -n 50
```

## Первый вход

При первом запуске, если пользователей ещё нет, панель сама заводит учётку
`admin` со случайным одноразовым паролем и печатает его в журнал. Панель
потребует сменить этот пароль сразу после первого входа — он больше нигде не
хранится, и если он потерян, единственный выход — удалить
`/etc/ssh_tunnel_panel/users.json` и перезапустить службу.

## Защита входа

- Пароль хранится хешем (bcrypt), не в открытом виде.
- Сессия — в cookie (`HttpOnly`, `SameSite=Lax`, `Secure` при HTTPS), а не
  токеном в адресе, как у локальной панели: адрес панели на VPS смотрит в
  интернет, и токен в URL слишком легко утекает — из истории браузера, из
  логов прокси перед ней.
- Подряд неудачные попытки входа тормозятся растущей задержкой, а после
  нескольких подряд — учётная запись на время блокируется. Подробности:
  `src/internal/panel/limiter.go`.

## Флаги

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `-listen` | `127.0.0.1:47823` | адрес, который слушает панель без `-domain` |
| `-domain` | — | включает HTTPS со встроенным автосертификатом на этот домен |
| `-data-dir` | `/etc/ssh_tunnel_panel` | папка с учётными записями и кешем сертификатов |
