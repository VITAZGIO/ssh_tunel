# Режим VPN (`ssh_tunnel_vpn.exe`, `ssh_tunnel_vpn_linux`)

Обычные `ssh_tunnel.exe` и `ssh_tunnel_linux` — это прокси: они работают только с теми программами,
которые умеют ходить через прокси (браузеры, curl, npm и т.д.). Программы,
которые про прокси не знают (часть игр, клиенты Docker, самописные утилиты),
идут мимо туннеля.

Версии с режимом VPN работают как настоящий VPN: создают в системе
виртуальную сетевую карту, и **весь** трафик компьютера идёт через неё — а
дальше через тот же SSH до твоего сервера. Настраивать отдельные программы не
нужно.

Со стороны провайдера разницы нет: и там и там он видит одно зашифрованное
SSH-соединение с сервером.

## Чем приходится платить

- **Права администратора** (на Linux — root). Создавать сетевые адаптеры и
  менять маршруты система разрешает только им. На Windows без службы окно UAC
  появляется при каждом запуске; со службой (галочка «Запускать при старте
  системы», см. ниже) — один раз, при её установке. На Linux запускать надо
  через `sudo`. Из-за этого режим VPN — отдельные файлы: обычные версии
  остаются без повышенных прав.
- **Размер.** Внутри exe сетевой стек (gvisor) и драйвер Wintun — файл больше
  обычного.
- Одновременно запускается что-то одно — обычная версия или VPN. Настройки и
  серверы у них общие (на Linux под `sudo` берутся из домашней папки того, кто
  запустил).

## Как это устроено

```
  любая программа
        │  обычные IP-пакеты
        ▼
  адаптер «ssh_tunnel» (Wintun)       маршруты 0.0.0.0/1 и 128.0.0.0/1
        │
        ▼
  сетевой стек gvisor                 пакеты → снова TCP-соединения
        │
        ▼
  ядро туннеля (то же, что у прокси)  правила, журнал, пул SSH
        │  SSH
        ▼
    твой сервер
```

- **Адаптер** — драйвер Wintun от авторов WireGuard. Он вшит в exe и при
  первом включении кладётся в папку настроек (`%APPDATA%\ssh_tunnel\wintun`).
- **Маршруты.** Весь интернет — двумя половинками (`0.0.0.0/1` и
  `128.0.0.0/1`), а не одним маршрутом по умолчанию: так наши маршруты всегда
  точнее маршрута настоящей сети. Своя локальная подсеть (роутер, принтер)
  точнее ещё и продолжает идти напрямую.
- **Петля.** Соединение с сервером и прямые соединения «мимо туннеля»
  программа открывает сама — и они тоже попали бы в адаптер. Поэтому каждый её
  сокет привязывается к настоящей сетевой карте (`IP_UNICAST_IF`). Сменилась
  сеть (Wi-Fi → кабель) — привязка меняется и пул переподключается сам.
- **DNS.** Адаптер объявляет свой DNS-сервер `198.18.0.53` — его обслуживает
  программа. На имя отдаётся подставной адрес из `198.18.128.0/17`, а
  настоящее имя разрешает сервер в момент соединения — как в прокси-режиме и
  на Android. Имена из «всегда напрямую» и локальной сети разрешаются
  по-настоящему, через DNS настоящей сети.
- **Защита от утечки DNS.** Windows рассылает DNS-запросы через все сетевые
  карты сразу. Чтобы провайдер не видел запросов и не подсовывал заглушки,
  ставятся фильтры брандмауэра Windows (WFP): DNS разрешён только через наш
  адаптер и самой программе. Фильтры живут в «динамической» сессии — если
  программа упадёт, Windows снимет их сама, и интернет не пропадёт.
- **Правила по программам** работают так же, как в прокси-режиме: владелец
  соединения виден по порту.
- **UDP** (звонки, игры, QUIC) — через ретранслятор на сервере, если он
  установлен и включён в настройках сервера. Иначе UDP отбрасывается, и
  браузеры сами переходят с QUIC на TCP.

## Обход блокировок и сеть устройств — по отдельности

На главном экране две кнопки:

- **большая** — обход блокировок: весь трафик идёт через сервер;
- **маленькая «Сеть устройств»** (видна, когда у сервера включена [сеть
  устройств](MESH.md)) — адреса `198.19.x.y` и имена `.mesh`, RDP и всё
  остальное между твоими устройствами.

Обе едут по одному SSH-соединению, но включаются и выключаются отдельно.
Выключил обход — сайты идут напрямую, а сеть устройств работает: адаптер
остаётся, но в нём только подсеть `198.18.0.0/15` (сеть устройств и наш
DNS), маршрутов всего интернета, DNS через VPN и запрета DNS мимо адаптера
больше нет. Переключение идёт на живом адаптере — открытые RDP-сессии не
рвутся. Туннель гаснет целиком, только когда выключены обе кнопки.

Имена `.mesh` без обхода блокировок разрешаются правилом NRPT (таблица
политик разрешения имён Windows: «зону `.mesh` спрашивай у `198.18.0.53`»),
как у Tailscale и NetBird. На Linux то же делает systemd-resolved доменом
`~mesh`; без resolved в этом режиме устройства доступны по адресам.

В прокси-версии выключенный обход снимает системный прокси, а туннель
остаётся ради сети устройств: к этому компьютеру можно подключаться с
других устройств, а сам он ходит к ним через SOCKS/HTTP-прокси программы.

## Автозапуск на Windows — служба

Галочка «Запускать при старте системы» в VPN-версии ставит **службу
Windows** — программу, которую система запускает сама при включении
компьютера, ещё до входа в учётную запись. Так устроены NetBird и Tailscale,
и даёт это то же самое: включил компьютер удалённо — он висит на экране ввода
пароля, а VPN и сеть устройств уже работают, к нему можно подключиться по RDP.

```
  при включении компьютера                     при входе пользователя
  ┌──────────────────────────────┐             ┌───────────────────────────┐
  │ служба ssh_tunnel_vpn        │  127.0.0.1  │ окно ssh_tunnel VPN (трей)│
  │ (SYSTEM): туннель, адаптер,  │◄────────────│ без прав администратора   │
  │ сеть устройств, веб-интерфейс│ service.json│                           │
  └──────────────────────────────┘             └───────────────────────────┘
```

- **Установка.** Галочка → окно UAC один раз. Программа копирует себя в
  `C:\Program Files\ssh_tunnel\ssh_tunnel_vpn.exe` (служба работает от имени
  SYSTEM, и её файл не должен лежать там, где его может подменить обычная
  программа) и ставит службу `ssh_tunnel_vpn`: автоматический запуск,
  перезапуск при сбое через 5/10/30 секунд. «Подключаться сразу при запуске»
  включается само — ради этого служба и ставится.
- **Настройки** — те же, что у окна (`%APPDATA%\ssh_tunnel`): служба получает
  папки пользователя параметрами `-profile` и `-appdata`. Драйвер Wintun
  служба кладёт в `Program Files`, а не в папку пользователя.
- **Сети при включении может ещё не быть** — служба ждёт её сколько угодно и
  подключается, как только она появится. Окно без службы ждёт три минуты.
- **Окно** — обычная программа без прав администратора, в автозагрузке
  пользователя (`HKCU\...\Run`, с ключом `-tray` — сразу значком в трее).
  Адрес и ключ веб-интерфейса службы оно берёт из `service.json` в папке
  настроек (туда может заглянуть только сам пользователь, администраторы и
  SYSTEM) и показывает его через свой маленький прокси: перезапуск службы
  открытое окно не ломает. «Выход» в трее закрывает только окно — VPN
  продолжает работать.
- **Журнал службы** — `%APPDATA%\ssh_tunnel\service.log`.
- **Обновление.** Запусти файл новой версии — он увидит, что служба работает
  на старой, и предложит обновить её (окно UAC). Если окно программы уже
  открыто, сначала выйди из него через трей.
- **Выключение.** Сними галочку → окно UAC → служба удаляется, окно
  перезапускается в обычном режиме (ядро в процессе окна, UAC при каждом
  запуске). Файл в `Program Files` остаётся, его можно удалить руками.
- Обычный `ssh_tunnel.exe`, запущенный при работающей службе, открывает окно
  VPN-версии: второй туннель поверх первого только мешал бы.
- Автозапуск прежних версий (запись в реестре, задача Планировщика) при
  первом запуске новой переносится на службу сам. Ярлык в папке
  «Автозагрузка», положенный руками, надо удалить.

Руками: `ssh_tunnel_vpn.exe -install-service` / `-uninstall-service` (от имени
администратора), состояние — `sc query ssh_tunnel_vpn`.

## Linux

```bash
# скачать (на ARM — Raspberry Pi и т.п. — возьмётся сборка _arm64) и сделать исполняемым
F=ssh_tunnel_vpn_linux; [ "$(uname -m)" = aarch64 ] && F=${F}_arm64
curl -fL -o ssh_tunnel_vpn_linux https://github.com/VITAZGIO/ssh_tunel/releases/latest/download/$F
chmod +x ssh_tunnel_vpn_linux

# задать сервер один раз
sudo ./ssh_tunnel_vpn_linux -host ТВОЙ_СЕРВЕР -user tunnel -save

# запустить с веб-интерфейсом — те же флаги, что у ssh_tunnel_linux
sudo ./ssh_tunnel_vpn_linux -web
```

Чтобы поднимался сам при загрузке — блок «Домашний сервер одной вставкой» в
[LINUX_SETUP.md](LINUX_SETUP.md) с `B=ssh_tunnel_vpn_linux`.

Устроено так же, как на Windows, со своими средствами системы:

- адаптер — устройство TUN `sshtun0`, адреса и маршруты задаются через
  netlink (интерфейс ядра для настройки сети);
- свои сокеты привязываются к настоящей сети через `SO_BINDTODEVICE`;
- DNS: если работает systemd-resolved — нашему интерфейсу ставится DNS
  `198.18.0.53` и домен `~.` (все запросы идут только туда); исчезнет
  интерфейс — resolved забудет настройку сам. Без resolved подменяется
  `/etc/resolv.conf`, прежний сохраняется в папку настроек и возвращается при
  выключении или при следующем запуске, если программа упала;
- служба systemd — `packaging/linux/ssh_tunnel_vpn.service`.

Маршруты и защита от петли проверяются тестом на настоящем ядре: он
запускается в отдельном сетевом пространстве имён и сеть машины не трогает
(`go test ./vpnlayer/` под root).

## Сборка

Нужен Go 1.26 (для сетевого стека), `curl` и `unzip`:

```bash
cd vpn
./build.sh      # скачает Wintun, сверит сумму, соберёт exe и файлы для Linux в ../releases
```

На GitHub то же делает workflow `vpn` на каждый пуш — готовые файлы лежат в
артефактах запуска.

## Что проверить руками (Windows)

Сетевой адаптер, маршруты, UAC и фильтры брандмауэра Windows в тестах не
проверить — только на живой системе.

1. Запуск: окно UAC, затем обычное окно программы с заголовком
   «ssh_tunnel VPN».
2. «Подключить» → в «Сетевых подключениях» появился адаптер `ssh_tunnel`.
3. https://2ip.ru (или любая проверка IP) показывает адрес сервера — в
   браузере **без** настроенного прокси.
4. Программа, не знающая про прокси (например, `curl` без флагов в cmd,
   `git`), тоже ходит через сервер.
5. Роутер (`192.168.x.1`) открывается — локальная сеть идёт напрямую.
6. Выключение Wi-Fi и включение обратно (или переключение на кабель) —
   через несколько секунд всё снова работает, без переподключения руками.
7. «Отключить» — адаптер исчезает, интернет работает как обычно.
8. Утечки DNS: https://browserleaks.com/dns — должны быть только DNS-серверы
   со стороны твоего сервера, не провайдерские.
9. Закрыть программу через диспетчер задач («Снять задачу») — интернет после
   этого должен работать сам, без перезагрузки.
10. Галочка «Запускать при старте системы» → окно UAC → в `services.msc`
    служба «ssh_tunnel VPN» (автоматически, выполняется), окно перезапустилось
    без прав администратора. Перезагрузить компьютер и **не входить** в
    систему: с другого устройства сети `ping имя.mesh` и RDP на него
    работают.
11. Вход в систему — значок в трее, без окна UAC; окно показывает состояние
    службы. «Выход» в трее — VPN продолжает работать.
12. Большая кнопка при включённой сети устройств: сайты идут напрямую
    (2ip.ru — свой адрес), а `ping имя.mesh` и открытая RDP-сессия живут.
    Маленькая кнопка выключает сеть, большая снова включает обход.
13. Снять галочку → окно UAC → служба удалена, программа перезапустилась
    в обычном режиме.
