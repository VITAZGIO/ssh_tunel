# Версия для Android — чего пока нет и что для неё нужно

Коротко: **приложения для Android пока нет.** Здесь честно написано, почему и
что именно нужно, чтобы оно появилось, — чтобы никто не тратил время на
поиски несуществующей ссылки.

## Почему нельзя просто пересобрать то же самое

Версии для Windows и Linux работают как **локальный прокси**: они поднимают
SOCKS и HTTP на 127.0.0.1, а система направляет туда трафик приложений.
В Android такого способа нет:

- общесистемной настройки прокси, которую можно поменять из приложения, там
  не существует — прокси в настройках Wi-Fi действует только на текущую сеть
  и только на часть приложений;
- переменные окружения на Android никто не читает;
- единственный настоящий способ увести трафик всей системы — это
  `VpnService`, то есть виртуальный сетевой интерфейс.

Из этого следует, что приложение для Android — **не сборка того же кода под
другую систему, а отдельная программа** с другой архитектурой.

## Что нужно сделать

1. **Приложение на Kotlin с `VpnService`.** Система отдаёт ему виртуальный
   интерфейс, в который сыплются сырые IP-пакеты.

2. **Слой tun2socks.** Пакеты из виртуального интерфейса надо разбирать и
   превращать в обычные TCP-соединения, которые уже можно вести через SSH.
   Это самая объёмная часть: разбор IP и TCP, отслеживание состояний
   соединений, сборка обратно.

3. **Ядро туннеля.** Вот его переписывать не нужно: `internal/tunnel`,
   `internal/routing`, `internal/speedtest` и остальное — обычный Go без
   привязки к системе. Их собирают в библиотеку `.aar` через `gomobile bind`
   и подключают к приложению.

4. **Выбор приложений.** На Android это делается штатно и даже проще, чем на
   Windows: `VpnService.Builder` умеет `addAllowedApplication` и
   `addDisallowedApplication` — ровно те же три режима, что уже есть в
   настройках, только список берётся из установленных приложений с их
   значками.

5. **Интерфейс.** Тот же экран, что в версии для Windows: состояние, круглая
   кнопка, плитки. Проще всего повторить на Jetpack Compose.

## Почему этого нет прямо сейчас

Для сборки нужны Android SDK и NDK, Gradle и `gomobile` — их нет в среде, где
писалась остальная часть проекта. Можно было бы написать несколько тысяч
строк Kotlin вслепую, но проверить их было бы нечем: не собрать, не запустить,
не отладить. Такой «результат» отнял бы у тебя больше времени, чем сэкономил.

Если версия для телефона нужна — это отдельная работа в среде с установленным
Android-инструментарием. Ядро к ней уже готово: оно кросс-платформенное и
покрыто тестами.

## Что делать на телефоне сейчас

Пока приложения нет, на Android остаются готовые клиенты, которые умеют SSH и
SOCKS: например **ConnectBot** (проброс порта по SSH) вместе с любым
браузером, поддерживающим SOCKS-прокси, или **Termux** с обычным
`ssh -D 1080`. Это не так удобно, как отдельное приложение, но работает через
тот же самый VPS и тот же ключ.
